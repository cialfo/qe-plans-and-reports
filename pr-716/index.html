Impact
Regression
Dashboards & Reports — Counselor Dashboard dashboard.component.ts indexes media[0] on custom assets; the normalization now applied in the service is what prevents the production crash — if that normalization regressed, the counselor dashboard would crash again for any school whose Airtable banner entry has no image.
Apps — Direct Apply da-section.component.ts and da-destination.component.ts both consume custom assets and index media[0] or call extractCustomAssets; the same null-guard now protects them, so regression in the service would surface here too.
Communications — Help Center & Guides cialfo-guide-widget.component.ts indexes media[0] on custom assets; it was not in the Nov 4 crash only because the affected schools' assets were of a different type, not because the guard was already there.

  2. Navigate to the counselor dashboard home page.
  3. Observe the top banner area.
 The banner carousel displays images and cycles through slides without any error. No JavaScript errors appear in the browser console. Any school currently showing a custom banner in production (e.g. one of the 31 schools affected on Nov 4 that has since had its image restored).
TP-002 Dashboards & Reports — Counselor DashboardTop banner carousel — asset without an image A school has a custom banner entry in Airtable with no image attached (media is absent). User is logged in as a counselor at that school.
  1. Log in as a counselor at a school that has a banner entry with no image.
  2. Navigate to the counselor dashboard home page.
  3. Observe the top banner area.
  4. Open the browser console and check for JavaScript errors.
 The dashboard loads without crashing. No slide is shown for the image-less entry. Any entries with images display as normal. No JavaScript errors appear in the console. A test school with an Airtable banner entry that has no image attached, or a development environment where the API can be made to return an asset with a null media field.
TP-003 Dashboards & Reports — Counselor DashboardTop banner carousel — stale cache with null media User is logged in as a counselor at a school with custom assets. Browser localStorage contains a cached assets entry for this user/student ID that includes an asset with null media (simulating a cache written before this fix was deployed).
  1. Using browser developer tools, open the Application tab and locate the localStorage key custom_assets_<id> for the counselor.
  2. Edit the cached JSON to set media: null on one of the asset entries and ensure the expiry timestamp is in the future.
  3. Reload the counselor dashboard without clearing localStorage.
  4. Observe the top banner area and check the browser console.
 The dashboard loads from cache without crashing. The asset with null media contributes no slide. Other assets display normally. No JavaScript errors. Browser with developer tools; an active counselor session at a school that has at least one custom asset so the localStorage key exists to edit.
