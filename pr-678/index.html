Notifications — Notification Preferences unknown (board-modules.json absent) The v5 API response for notification preferences no longer returns sms_enable. Any existing test that asserts the full payload shape, or that toggles an SMS preference, will fail or exercise dead UI. The notification-preferences screen must render and save correctly with only email, in-page, and push toggles present.
People / Team Settings — Notification Table unknown (board-modules.json absent) The SMS column header and per-row SMS checkbox are removed from the Add-People notification preferences table. Tests covering that screen's table structure or its save flow need re-running to confirm no rendering regression and that saving email/in-page preferences still persists correctly.
Student List — Add Student & Bulk Actions unknown (board-modules.json absent) Three visible copy strings changed: the Add Student dialog's registration toggle now says 'email' (not 'email/SMS'), the bulk-send confirmation dialog says 'Send Registration Email' (not 'Email/SMS'), and the success toast says 'Registration emails sent' (not 'emails/SMS sent'). Existing tests that assert on the old copy will fail; manual smoke tests should confirm the correct strings appear.
Bulk Uploads — Upload Wizard unknown (board-modules.json absent) The activation-link toggle on the wizard's final step was renamed (sendSmsActivationLink → sendActivationLink) and its label changed from 'SMS/email' to 'email only'. The data-test attribute also changed from 'uploads-wizard-sms-toggle' to 'uploads-wizard-activation-link-toggle'. Any e2e selectors using the old attribute will not find the element. The toggle must still default to checked and behave correctly on the wizard submit path.
Tuition Fees — Forward Payment unknown (board-modules.json absent) The SMS branch (phone input, mobile display, 'Send SMS' button copy) is removed from the forward-payment modal. The modal now presents only the email path. Existing tests covering the modal's render or submit should be re-run to confirm no breakage, and the email forwarding flow must still complete successfully end-to-end.
Notifications — Email Delivery (Reminders, Welcome, UEA) unknown (board-modules.json absent) The API no longer sends SMS for meeting reminders, welcome/registration messages, or UEA engagement approval requests. While this is a removal, the email path for each of these must still fire correctly. A broken SMS branch that was silently swallowing the whole notification would mask an email regression.
